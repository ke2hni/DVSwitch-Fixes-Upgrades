# DVSwitch M17 Private-Node Switching Support

<!-- Version: 1.7.0; Created: 2026-11-09T00:41:12-05:00 by KE2HNI; Updated: 2026-11-21T15:45:00-05:00 by KE2HNI — document matching completed M17 activity to the callsign from its start event. -->

This component provides two commands for an ASL node that has an M17 USRP private-node stanza and DVSwitch's Analog_Bridge private-node stanza:

- `m17` disconnects any connected external ASL nodes and other private USRP links from the public ASL node, then connects the configured M17 private node.
- `dvs-dvswitch` disconnects other private USRP links, then connects the explicitly selected DVSwitch private node.

The commands switch local private-node links. M17 activation also disconnects existing external ASL links before changing private audio paths, preventing the public node from remaining linked to both an external node and M17. They do not install an M17 reflector client, create the M17 Asterisk stanza, or select reflector destinations. The install script prompts for both private node numbers (M17 defaults to `1972`); both values are stored in `/etc/dvswitch-m17-support.conf`. It installs `/usr/local/bin/m17` and `/usr/local/bin/dvs-dvswitch` as symlinks to root-owned command files.

M17 Support owns its node selection and switch helper; it does not require ASL 3 Support or Mode Buttons to be installed. Option 7 asks for the M17 and DVSwitch private node numbers, then installs an M17-owned helper that switches the public ASL node exclusively between them, preventing private-node audio crossfeed. It reads the installed `/etc/asterisk/rpt.conf` and disconnects other private USRP links before connecting the selected node. The installer backs up its config, command links, helper, and wrappers under `/var/backups/dvswitch-mods/m17-private-node-switch/`.

The install output identifies the backup folder. Restore it from the combined repository root with `sudo ./DVSwitch-M17-Support/dvswitch-m17-support.sh --restore install-YYYYMMDD-HHMMSS`; pass the actual folder name reported by your installer. Restore also saves the current files to a `pre-restore-*` recovery folder.

Run `sudo PYTHONDONTWRITEBYTECODE=1 python3 DVSwitch-M17-Support/tests/test-m17-support-installer.py` and `python3 DVSwitch-M17-Support/tests/test-m17-exclusive-node-switch.py` from the combined repository root to exercise the installer's check, fresh-install, upgrade, already-installed, partial-install resume, restore, and collision-guard paths in a temporary tree.

## Full USRP2M17 bridge installation

The command installer above only installs the mode-switch commands. To install the actual M17 network bridge, choose manager option 8 directly; the bridge installer asks which private node is used by DVSwitch and which separate private node is used by M17. It adopts the M17 node number saved by option 7, including a pre-existing USRP stanza, and treats the ports in that reserved stanza as expected Asterisk bindings. It changes only that stanza's `rxchannel` when needed; its original channel is restored on uninstall if it has not been changed since installation. A valid existing local IAX node mapping is preserved, including a configured non-default local port. The non-secret `/etc/USRP2M17.ini` is owned by `asl:asl` and installed with mode `0644` so Apache can read it to render the M17 Net card and dashboard target. Re-running option 8 upgrades older installs and repairs this permission when the file was created with mode `0600`; the dashboard's audio monitor also needs to read this file. During compilation, a temporary copy of upstream C++ source receives missing fixed-width integer header includes where needed; the upstream checkout remains unmodified. The interactive installer downloads and builds USRP2M17 from the upstream nostar/MMDVM_CM GitHub repository, configures the reflector and Asterisk private node, and creates a systemd service. It also installs or updates the independent M17/DVSwitch exclusive-switch commands.

Follow [INSTALL-USRP2M17.md](INSTALL-USRP2M17.md) for the complete first-time instructions, verification commands, and uninstall procedure. The interactive installer can also be run directly from the combined repository root with `sudo ./DVSwitch-M17-Support/dvswitch-m17-bridge.py`.

## M17 dashboard integration

After USRP2M17 and the M17 private-node commands are installed, choose manager option 9 and select **Install or upgrade M17 dashboard support**. Option 9 is independent of DVSwitch Mode Buttons (option 2): with Mode Buttons installed, M17 uses its shared toolbar and favorites editor; without it, this component supplies its own M17 button, tuning controls, and editable favorites. You can install option 2 before or after option 9. Upgrading dashboard support refreshes the status endpoint and restarts the M17 RX monitor so new receive-heartbeat code is loaded by an already-running service. If the bridge was installed before this dashboard release, run manager option 8 and choose **Install or upgrade USRP2M17** once so the bridge logs include callsigns at both voice start and end. The dashboard adds an M17 Net card and M17 events to the existing Gateway Activity and Local Activity tables. The main Gateway Activity row appears with the callsign and an `RX M17` indicator during a live network call; after the transmission ends, that same callsign row shows its completed duration. TRX Info stays on `RX M17` through brief heartbeat gaps, then returns to listening after audio stops. Reflectors are downloaded from the M17 Project's `M17Hosts.json` catalog weekly; catalog refreshes do not rewrite editable favorites. Initial favorites are seeded once with one entry per usable reflector (module A when available, otherwise its first M17 module), and subsequent edits and deletions are kept. The M17 toolbar has a separate reflector catalog dropdown and module dropdown beside RX Monitor; choosing a catalog entry fills the target field but does not tune until **Tune** is pressed. Catalog entries are not favorites, and the Favorites dropdown/editor remain independent. The module list shows only supported M17 modules (alphabetical in the picker); module A is selected when available, otherwise the alphabetically first module. To save the selected catalog target, use **+ Favorite**.

M17 reflector labels use the catalog `name` when it contains a usable value. If `name` is JSON `null`, blank, or the text `null`, the dashboard uses a usable `sponsor`; when both fields are missing or invalid, it shows only the reflector designator as the friendly label. Gateway Activity still appends the full reflector ID in parentheses. Existing history rows with a null label are resolved by the same rule when displayed.

The install-state directory is set to mode `0755` so Apache can test whether M17 dashboard support is installed and show the M17 mode button in the shared toolbar. The install-state file remains root-only (`0600`). When the shared toolbar is absent, the M17-owned dashboard script renders a standalone M17 control row instead.

In M17 mode, Analog Bridge Info displays the reflector/module identifier (for example `M17-404-A`), and the M17 Net card shows that identifier together with the catalog friendly name. Its friendly name uses the same copper text color as other network cards in dark mode. M17 activity stays in the main Gateway Activity table alongside the other modes, with targets formatted as `Friendly Name (M17-404-A)`, live callsigns shown as `RX M17`, and completed durations replacing the live indicator for that callsign. Each event uses the reflector selection recorded at its start; the end log entry supplies its duration and closes the same M17 or USRP stream, while the start entry supplies the caller callsign and timestamp. This handles USRP2M17 logs where the end line reports the reflector/gateway callsign (such as AE5ME), not the remote caller. Later tuning does not relabel older rows. If an event predates the saved history, it uses the first recorded reflector rather than changing to the current selection. The older dedicated M17 Gateway Activity panel is removed during layout startup.

The M17 reflector history is readable by Apache so Gateway Activity can resolve each event to `Friendly Name (Reflector-ID)`. The installer corrects permissions on existing history files during upgrade, and reflector changes keep newly appended history readable. Without readable history, activity rows fall back to the generic `M17 reflector` label.

When M17 is the selected dashboard mode, the Analog Bridge Info card shows `M17` and the configured M17 reflector/module in its visible mode and target rows. The diagnostic tooltip continues to show Analog_Bridge's actual telemetry. The RX Monitor button changes in place to **M17 RX Monitor** and plays decoded PCM from USRP2M17's configured loopback audio port through an M17-only local WebSocket monitor; it does not use DVSwitch's generic port 8080 stream. Leaving M17 stops that stream and restores the normal RX Monitor action. A root-owned service mirrors only the configured loopback packets, and Apache exposes it through a same-origin WebSocket proxy.

Selecting a favorite updates `/etc/USRP2M17.ini` and restarts `usrp2m17.service`. Selecting the already-active room does not restart it. The installer makes a dated config backup for each reflector change and restores the prior config if the service fails to restart. M17 uses the private node already configured by manager option 8, and the mode button switches the public node between the selected M17 and DVSwitch private links.

Uninstall dashboard support with manager option 9 and select **Uninstall M17 dashboard support**. This removes its card/history hooks, M17 controls, catalog timer, and dashboard helpers. It preserves USRP2M17, the M17 configuration, reflector catalog, and user favorites.


The M17 dashboard layout places the eight network cards in alphabetical order around Gateway Activity. Each network card keeps a rounded panel outline matching Analog Bridge Info. The first three cards sit in the left status sidebar below Analog Bridge Info and TRX Info; M17 Net and the remaining four cards sit in the right column, offset down 21 pixels to line up with the left status stack. The left and right card columns use equal widths and balanced outer insets, centering Gateway Activity between them. Gateway Activity and Local Activity share the same width and have equal gaps to the side card columns. Local Activity has additional separation below Gateway Activity. Analog Bridge Info keeps its row labels on one line. Refreshed status data replaces old card renders without making the cards flash or accumulate copies. BM and TGIF use one stable DMR card identity, so changing the heading between `DMR BM Master` and `DMR TGIF Master` updates the existing panel instead of leaving a stale duplicate. Mode buttons are alphabetized. The M17 reflector name retains the normal copper color in dark themes; the existing light-theme overlay darkens that label to `#6b2f00` for contrast.

The M17 selector reads the chosen module's UDP port when the catalog provides one, otherwise the reflector row's port, and defaults to 17000 when neither is present. An explicitly configured invalid port is rejected with a clear error.


The standalone M17 Tune field shows 12 characters. When shared Mode Buttons and ASL support are installed, digital target entry likewise displays 12 characters while ASL node entry remains 10 characters; the 35-character input limit and target validation are unchanged.
