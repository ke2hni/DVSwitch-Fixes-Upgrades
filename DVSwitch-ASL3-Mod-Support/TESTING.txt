ASL dashboard integration test procedure

These checks are for an ASL 3 test node. They do not install anything on a node.

Run the patcher tests from the combined repository root:

PYTHONDONTWRITEBYTECODE=1 python3 DVSwitch-ASL3-Mod-Support/tests/test-dvswitch-asl-mode-switch-patcher.py
PYTHONDONTWRITEBYTECODE=1 python3 DVSwitch-ASL3-Mod-Support/tests/test-asl3-dashboard-layout.py
PYTHONDONTWRITEBYTECODE=1 python3 DVSwitch-ASL3-Mod-Support/tests/test-asl3-support-integration.py
PYTHONDONTWRITEBYTECODE=1 python3 DVSwitch-ASL3-Mod-Support/tests/test-asl3-rpt-conf.py
PYTHONDONTWRITEBYTECODE=1 python3 DVSwitch-ASL3-Mod-Support/tests/test-asl3-usrp-ports.py
PYTHONDONTWRITEBYTECODE=1 python3 DVSwitch-ASL3-Mod-Support/tests/test-asl3-ami-status.py
PYTHONDONTWRITEBYTECODE=1 python3 DVSwitch-Mode-Buttons/tests/test-dmr-network-fast-path.py
sudo PYTHONDONTWRITEBYTECODE=1 python3 DVSwitch-ASL3-Mod-Support/tests/test-asl3-connect-replaces-external-links.py

On a test node, check compatibility without changing installed files:

sudo ./dvswitch-asl3-mod-support.sh --check

If the check passes, install ASL Support on pi4test. Mode Buttons is optional;
this ASL installation provides its own button and node controls:

sudo ./dvswitch-asl3-mod-support.sh --install

The installer compares the private node's USRP `remote-port:local-port` with
Analog_Bridge's `[USRP]` `rxPort` and `txPort`. If they differ, it backs up
Analog_Bridge.ini, applies the reciprocal port values, and restarts
Analog_Bridge. Check the listeners with `sudo ss -lunp | grep -E ':(31001|32001|34001|2222)([[:space:]]|$)'`; the configured pair for the test `34001:32001` should leave Analog_Bridge listening on `34001` and Asterisk on `32001`. A prior capture during received ASL audio showed no UDP packets on port 2222, so do not repeat that capture before checking the HTTPS WebSocket route below.

BM/TGIF preset switching must preserve the active Analog_Bridge `[USRP]` `txPort`/`rxPort`; older saved presets may contain `31001/31001` and must not replace the ASL pair. The regression test above reproduces switching from a stale preset and verifies the live ASL pair survives while the DMR talkgroup setting changes. For on-node validation after updating Mode Buttons, switch to BM or TGIF and back to ASL, then confirm the configured ports and process listeners still match the private node's USRP mapping before testing monitor audio.

If an earlier Mode Buttons build joined the USRP port lines and `--check` reports a missing `rxPort`, restore `/opt/Analog_Bridge/Analog_Bridge.ini` from the timestamped ASL backup named `opt__Analog_Bridge__Analog_Bridge.ini`, then run the USRP port helper in `install` mode and restart `analog_bridge` before testing again.

After install, activate the new ASL activity hooks on the test node:

sudo asterisk -rx "module reload app_rpt.so"

Then verify in the dashboard:

1. Select ASL. Confirm the button remains selected after status refresh and
   the private-to-public bridge is established if it was down. Confirm mode
   selection does not connect an external node, even if an older ASL target is
   saved. External links require a node entry and Tune.
2. Confirm the Analog_Bridge field label changes from `Tx TG/Ref` to `Node`.
3. Confirm the ASL Net card appears in the left status column with the other
   network cards. With an ASL link active, confirm it shows the remote node and
   friendly name from `astdb.txt`; after disconnecting or rebooting with the
   remote link gone, refresh the page and confirm it returns to `Listening`.
   Confirm Gateway Activity keeps its `Src` header after refresh.
4. Enter a numeric AllStar node in Tune; verify the connection is made through
   the discovered local public node then use **+ Favorite** to save a named ASL
   Favorite. Confirm that name overrides the ASTDB name in the activity card.
   On pi4test, confirm parrot 55553 reaches `ESTABLISHED` in
   `sudo asterisk -rx "rpt lstats 446901"`; private node 1970 remains the bridge.
   Confirm `Disconnect before Connect` is checked by default. With node 55553
   connected, enter a different node and select Connect; confirm the old
   external link drops before the new one connects, while the private bridge
   remains established. Repeat with the checkbox cleared and verify Connect
   leaves other external links alone.
5. Verify each checkbox action: Connect (ilink 3), Disconnect (ilink 1), Monitor
   (ilink 2), and Local Monitor (ilink 8).
6. With the private-to-public bridge and at least one external node connected,
   record `sudo asterisk -rx "rpt lstats <local-public-node>"`. Select Disconnect
   All. Confirm each external peer is disconnected individually and the private
   bridge peer remains established. Do not use `ilink 6` for this check.
7. Connect an external node again, then select a different DVSwitch mode.
   Confirm the external ASL peer is disconnected before the mode changes and
   the private-to-public bridge remains established. Confirm the selected mode
   works after the switch.
   Repeat the mode switch with the private-to-public link down; it must not
   report that the public node cannot be found or block the mode change.
   Also verify standard mode changes outside ASL (TGIF to STFU, STFU to NXDN,
   and NXDN to P25). Record click-to-Analog_Bridge and click-to-green timing.
   Each button reports its selected color only after its mode command finishes.
   Switch to YSF and leave the dashboard open through multiple status refreshes;
   the YSF button must remain selected while Analog_Bridge reports YSFN or YSFW.
   When exiting ASL, confirm the external peer is disconnected before the new
   mode is applied; ASL Support performs this cleanup inside the repaired
   `dvswitch.sh` path and preserves the private bridge.
8. Keep external node 55553 connected. Confirm ASL Gateway Activity uses the
   same `Time`, `Mode`, `Node`, `Name`, `Target`, `Src`, `Dur(s)`, `Loss`, and
   `BER` columns as Gateway Activity, with Loss at `0%` and BER at `0.0%`.
   Confirm the public node's RX/TX and remote PTT activity follows Allmon3 while
   another node sends audio; duration advances while keyed. Disconnect 55553
   and confirm it disappears. Reboot and confirm only peers that reconnect are
   listed.
9. Test RX Monitor while another node sends audio to the connected node. On an
   HTTPS dashboard, confirm the browser opens
   `wss://<dashboard-host>/dvswitch-audio/` and that audio plays. Also confirm
   non-ASL mode buttons, Tune/Favorites, and services still behave as before.

Earlier versions were validated on pi4test for ASL-to-P25, NXDN, DMR, D-Star,
YSF, and STFU switching, and ASL RX Monitor audio was confirmed working. This
release changes ownership and adds an independently managed ASL dashboard
button, so repeat the migration test on pi4test before proceeding.

After pi4test passes, proceed to pi5test, then test3040. Do not install on
production nodes without explicit authorization.

The ASL support installer backs up dashboard files, helpers, favorites, and rpt.conf under
/var/backups/dvswitch-mods/asl3-support. The standalone dvswitch.sh repair keeps
its own backup under /var/backups/dvswitch-mods/asl-mode-switch.

10. In ASL mode, enter a node but leave all action boxes unchecked; Tune must
    not issue a link command. Select Connect and Tune; confirm the external
    node ID appears in Analog Bridge Info and the ASL Gateway Activity card.
    Confirm the card matches Gateway Activity styling in light and dark modes.
11. Leave ASL selected and watch Analog Bridge Info through multiple status
    refreshes; the target label must remain `Node`. Confirm the ASL Node Link
    box is compact and stays usable at narrow browser widths.
12. From ASL, select each supported digital mode once. Confirm the dashboard
    reports an error rather than changing its saved selection if Analog_Bridge
    remains in ASL; after a successful switch, confirm the selected mode and
    Analog_Bridge status agree without a browser refresh.

13. With Mode Buttons installed but ASL Support absent, run its `--check` and
    confirm it reports the legacy ASL button for removal. Install Mode Buttons
    and confirm the embedded ASL button disappears while all seven standard
    modes and their Favorites continue to work. Then install ASL Support and
    confirm its ASL-owned button and node tuner appear beside the standard modes.
14. Repeat the ASL Support install with Mode Buttons absent on a disposable test
    image; confirm ASL still provides its own mode button, node controls, and
    favorites without installing or invoking the Mode Buttons installer.


Version 1.1.0 dashboard and exit checks:
1. Install ASL Support with Mode Buttons installed. Confirm there is one ASL button, one Tune/Favorites row, and no second ASL target row. In ASL mode confirm the Analog_Bridge label reads `Node`, the field shows the connected external node, the shared input says `Enter Node #`, and the link card has the five actions plus checked `Disconnect before Connect`.
2. Select Connect and Tune with node 55553; confirm the UI reports `Connected to Node 55553` and `rpt lstats` on the discovered public node lists it. Leave every action unchecked and press Tune; confirm no link command runs. Confirm favorites use ASTDB names by default and allow a custom name.
3. From ASL with 55553 connected, click one digital mode once. Confirm external peers are removed from the public node while the private bridge remains, then the requested digital mode command runs once. Record click-to-mode time; it should complete within six seconds. Repeat for each digital mode. The dashboard must not return to ASL or flicker after status refreshes.
4. Reload the page in ASL. Confirm the ASL button and Node label reflect current Analog_Bridge status and the Tune/Favorites row remains singular. Repeat with Mode Buttons absent on a disposable image; ASL Support must still provide its ASL button, node action row, and favorites.
